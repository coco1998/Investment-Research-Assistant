# 管访清单 Skill

## 角色

基于已有研究产出（pre-jdg/ind-res/comp-res 至少一个），生成分对象、分优先级的管访问题清单。回答「在有限时间里，最应该问什么、怎么判断回答质量」。

## 前置依赖
- 必须基于 ind-res / comp-res / pre-judge（至少做过一个）的待验证问题
- 当项目文件夹内有更多材料（管访纪要/专家访谈/客户访谈/竞对列表）时，必须先做材料挖掘

## 12 类对象框架

| 内部人员 | 外部人员 |
|------|------|
| CEO/创始人、CTO/技术负责人、COO/运营负责人、CFO/财务负责人、销售/商务负责人、产品负责人 | 客户、供应商、竞对、行业专家、离职员工、投资人 |

有 datapack 时用「姓名 — 职位」，不用通用角色标签。

## 工作流程


**项目上下文重置（防串项目）**：开始撰写前，确认当前项目名称。报告中所有案例/竞品/数据/人名必须来自当前项目。不可复用上一项目的分析框架作为模板代入。

### 材料检查（强制）
研究前扫描项目下所有已有访谈（见闻录 + 本地访谈文件）。访谈是最高质量的一手信息——必须逐份检查是否有可用素材，不可仅依赖 BP/Datapack。

### Step 1：材料挖掘（硬要求）
扫描全部可用材料（BP/Datapack/管访纪要/专家访谈/客户访谈/竞对列表），提取：
- 人名与角色 → 明确访谈对象
- 技术 Claim（控制频率/数据效率/泛化能力等）→ 形成对质问法
- 客户与订单数据 → 交叉验证
- 矛盾/分歧点（不同来源说法不一致的地方）→ 最高优先级
- **强制**：输出「信息一致性检查表」——同一事实的不同来源说法对比，标注一致/不一致/待验证

### Step 2：对象分配
按 P0/P1/P2 分配问题到具体对象：
- **P0**：决定投不投的核心问题，必须在本次管访中搞清楚
- **P1**：影响判断但可后续补充的问题
- **P2**：锦上添花，时间允许才问

### Step 3：撰写
每条问题含：题干 + 判断标准（✅ 满意回答 / ❌ 红旗信号）

**数字追问模板（强制）**：每个关键维度（产品/客户/产能/成本/财务，以及该行业的核心性能指标），必须至少有一个量化追问。追问格式：**「当前数字是多少？下一个 milestone 的数字目标是多少？什么时候？」**——三个要素缺一不可。如果材料中已给数字但口径不一（如 BP 预测 vs 业务口径 vs 第三方数据偏差 >30%），追问偏差根因。不同行业的量化指标不同——不套用固定清单，根据该行业的 KSF 和材料中已出现的数据维度来确定追问方向

**硬伤核查列表（强制）**：如果 pre-jdg 硬伤检查触发了任何 P0 事项（创始人诚信/IP归属/股权代持/客户集中度/数据合规/融资造假），必须设计对应的对质问法写入管访清单。不可遗漏。

## 输出结构

```markdown
# [公司] 管访清单 v[N]

> 基于：[前置报告列表] | 访谈场次计划：[N] 场

## 1. 来源分层
（本次清单基于哪些已有材料——逐项列出报告名+见闻录 link，标注版本号。）

## 2. 信息一致性检查
（强制表格——同一事实的不同来源说法：

| 事实 | 来源A说法 | 来源B说法 | 一致性 | 追问方向 |
|------|------|------|:---:|------|
| [事实描述] | [说法+来源] | [说法+来源] | ✅/⚠️/❌ | [如果不一致，怎么问] |

至少 3 行。）

## 3. 对象分配总览
（强制表格——对象/角色/优先级(P0+P1+P2题数)/建议时长：

| 对象 | 角色 | P0 | P1 | P2 | 建议时长 |
|------|------|:---:|:---:|:---:|:---:|
| [姓名] | [职位] | N | N | N | XX min |

有 datapack 时强制用「姓名 — 职位」格式。）

## 4. 分对象访谈提纲

### [对象姓名] — [职位]
（每个对象独立小节。按 P0 → P1 → P2 排列问题。）

#### P0 — 必须搞清楚

| # | 问题 | 问法类型 | 判断标准 |
|---|------|:---:|------|
| P0-1 | [题干] | 开放式/对质式/量化追问 | ✅ [满意回答特征] / ❌ [红旗信号] |
| … | | | |

#### P1 — 重要补充
（同上格式）

#### P2 — 时间允许
（同上格式。≤3条。）

---

（重复以上结构覆盖全部访谈对象。）

## 5. 跨对象交叉验证设计
（强制——同一假设从不同对象角度提问的矩阵：

| 关键假设 | 问 [对象A] | 问 [对象B] | 判断：一致则验证/不一致则深挖 |
|------|------|------|------|
| [假设] | [问法] | [不同角度的问法] | |

至少 3 条交叉验证对。）

## 6. 硬伤核查问题（如有触发）
（如果 pre-jdg 触发了六项硬伤检查中的任一项，此处列出对质问法。格式同上。如无触发，标注「无触发项」。）
```

## 自检清单

- [ ] 信息一致性检查表 ≥3 行？标注了一致/不一致/待验证？
- [ ] 对象分配表每行有 P0/P1/P2 计数+建议时长？
- [ ] 每条问题有判断标准（✅满意 / ❌红旗）？
- [ ] 每个关键维度有 ≥1 个量化追问（数字+目标+时间三要素齐全）？
- [ ] 跨对象交叉验证设计 ≥3 对？
- [ ] pre-jdg 硬伤检查触发的 P0 事项是否全部设计了对应的对质问法？
- [ ] 有 datapack 时访谈对象是否用「姓名 — 职位」而非通用标签？
- [ ] 管访后自动扫描规则（详见 CLAUDE.md「管访清单规则」）：管访完成+新见闻录导入后，是否记得扫描已有报告并输出「可更新报告清单」？
