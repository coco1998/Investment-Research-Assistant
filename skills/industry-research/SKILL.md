# 行业研究 Skill

## 两种模式

| | 模式一：围绕公司 | 模式二：纯行业 |
|---|---|---|
| 触发 | 项目下有 pre-jdg | 用户直接指定行业 |
| 必要输入 | pre-jdg 产出（C级必须） | 行业界定范围（必须） |
| 输出位置 | `项目/[项目名]/行业研究_v[N].md` | `行业研究/[赛道名]-专题行研-[日期].md` |

## 前置依赖与下游

- 前置：pre-jdg（模式一，C）
- 子模块：tech-research（技术驱动赛道自动调用）；**竞对研究 → 硬门禁调用 competitor-analysis**
- 下游：→ comp-res（C） → fin-mod（B） → ic-report（B）

## 核心原则

1. **KSF 从难点推导**：每个 KSF 必须回答「为什么这个难」→「具备什么能力才能克服」→「具备这个能力的玩家是谁」
2. **竞对分析不手写**：硬门禁调用 competitor-analysis，从结构化数据文件引用，不内联重写
3. **来源标注**：关键数据标注来源类型（一手/二手/推断），多源交叉验证
4. **回答「谁能赢、为什么」**，不做公司罗列

## 工作流程


**项目上下文重置（防串项目）**：开始撰写前，确认当前项目名称。报告中所有案例/竞品/数据/人名必须来自当前项目。不可复用上一项目的分析框架作为模板代入。

### 材料检查（强制）
研究前扫描项目下所有已有访谈（见闻录 + 本地访谈文件）。访谈是最高质量的一手信息——必须逐份检查是否有可用素材，不可仅依赖 BP/Datapack。

### 第〇步：确定模式 + 前置检查
- 读 pre-jdg（模式一）→ 提取赛道关键词
- 问用户：行业边界、是否有额外参考资料
- 检查 comp-ana 数据文件是否存在（不存在→阻断，强制调用 competitor-analysis）
- 检索知识库：读 `知识库/2_wiki/index.md` → 定位相关 entities/concepts

### 第一步：检索
- **先执行领域自主学习检索（强制）**：①结构检索——「[行业名] 分类/技术路线对比」→建立分类树。②标准检索——「[行业名] 核心指标/性能参数」→理解这个行业怎么衡量好坏。结果写入报告「行业/技术基础」节。详见 CLAUDE.md「领域自主学习原则」
- 规划关键词 → 定向检索（官网/研报/融资数据/产业上下游）
- 优先读 Master「参考资料」节的精选文章

### 第二步：结构化分析
- 行业定义 + 核心矛盾
- 代际/阶段划分（标志性事件 + 未解决问题）
- 技术路线强制推导：原理→本质→现状→难点→KSF→投资判断。路线演进必须有**时间轴+阶段命名**（如「2027-29规模化导入期」），不可只用「2-3年后模糊表述」
- 落地场景分类（客户/需求/付费意愿/TAM量级）
- 市场空间 TAM/SAM/SOM + 多口径对比。**TAM必须公式化拆解**：出货量×单价×渗透率×其他因子，每步标注假设和来源。至少3年数据行（2025A/2026E/2028E），不可只列总规模
- **TAM 必须按技术路线/细分市场维度拆分**（模式一强制）。不只列总市场→标的总市场→标的可获取市场。**必须增加一个拆解维度**：按行业内的技术路线/产品路线拆分，标注每条路线的份额变化趋势。直接回答 IC 核心问题：「标的选的这条路到底有多大？」如果行业不存在清晰路线分化，标注「不适用」并说明原因
- 产业链与利润池

### 关键假设集中声明（强制）

报告必须包含假设表，每个量化结论回答「如果这个数错了会怎样」：

| 假设 | 数值/方向 | 依据 | 敏感性 | 如果出错的后果 |
|------|:---|------|:---:|------|

> **公司自述数据必须标注「未独立验证」**。引用公司 IC memo/BP 的市场数据时不可作为事实使用。

### 数据缺口清单（强制）

报告末尾必须列出未覆盖的信息及其对判断的影响：

| 缺口 | 对判断的影响 | 建议解决方式 |
|------|------|------|

### 来源可靠性

关键数据标注来源类型和权威性：[一手/官方] > [权威二手/头部券商+咨询] > [行业媒体] > [推测]。核心判断至少 2 个独立来源交叉验证，单来源标注「待验证」。所有量化判断必须有数字——不用「市场很大」「增长很快」等无参照物描述。

### 风险前置

报告必须包含一个明确的风险场景：「什么情况下这个赛道不值得布局？」不只写利好。

### 第三步：竞争格局（引用 comp-ana）
- 从 competitor-analysis 数据文件提取 KSF 矩阵/技术对比/公司档案
- 竞争关系图（ASCII）+ 代际差距 + 场景推演

### 第四步：投资结论
- 赛道判断 + Timing + KSF 排序 + 布局策略
- **Timing 判断必须回答「为什么是现在，不是 3 年前也不是 3 年后」**（强制）。从至少两个维度回答（具体维度根据行业选择，不套固定模板）：供给端触发（什么技术/供应链/人才条件近期成熟）、需求端触发（什么需求从 nice-to-have 变成 must-have）、资本周期触发（融资窗口打开/关闭）、竞争格局触发（为什么现在竞争密度合适）。不做高瓴四维度的机械套用——不同行业关键触发因素不同，但「为什么是现在」这个问题本身 mandatory
- 风险矩阵（概率 + **影响** + 可缓解性，三列缺一不可）
- 退出路径（IPO/并购概率和路径，至少 2 条）
- 关键观察指标（什么信号确认 thesis→加仓，什么信号否定 thesis→止损）

## 输出结构

```markdown
# [赛道] 行业研究 v[N]

> 版本说明行：模式一/二 + 基于哪些前置材料

## 核心判断
（赛道判断 + Timing + KSF排序（强制——每项KSF标注权重%）+ 布局策略。4-6句话。）

## 1. 行业定义与核心矛盾
（一句话定义 + 核心矛盾——这个行业最大的 tension 是什么。如果是v2更新，标注 🆕 新识别出的行业级瓶颈。）

## 2. 市场空间
（TAM 强制表格——至少3年数据行：

| 年份 | 端侧AI芯片TAM | 驱动 |
|------|:---:|------|
| 2025A | ~XX亿 | … |
| 2026E | ~XX亿 | … |
| 2028E | ~XX亿 | … |

表后跟「按技术路线拆分」子表（模式一强制）：

| 路线 | 2025 | 2028E | 趋势 |
|------|:---:|:---:|------|
| [路线A] | XX% | XX% | ↑/↓/→ |
| … | | | |

标注来源和假设。）

## 3. 技术路线全景
（强制表格——路线/代表/状态/核心瓶颈。4-6行。表后跟 🆕 行业级瓶颈分析（如适用——比如全行业软件工具链不成熟）。）

## 4. 竞争格局
（引用 comp-ana 数据文件。竞争对比表——竞对/差异化/威胁程度。每行必须有一句话差异化判断，不是名字罗列。表后跟竞争护城河判断——行业级稀缺资源是什么。）

## 5. 投资含义
- 确定性机会
- 最大变量/风险
- 最佳策略
- 关键观察指标（确认 thesis + 否定 thesis 各 ≥2 条）

## 6. 关键假设
（强制表格）

## 7. 数据缺口
（强制表格）

## 信息来源
（精简表格：来源 | 关键内容）
```

## 自检清单
- [ ] KSF 是否从难点推导（每个 KSF 能回答「为什么这个难」→「需要什么能力」→「谁具备」）？
- [ ] 竞对分析是否引用 comp-ana 数据文件（非手写）？
- [ ] TAM 是否公式化拆解（出货量×单价×渗透率）+ 按技术路线拆分？
- [ ] 关键假设表是否 ≥4 行？每行标注了敏感性和出错后果？
- [ ] 数据缺口表是否列出了对判断有实质影响的缺口？
- [ ] Timing 判断是否回答了「为什么是现在」≥2 个独立维度？
- [ ] 风险矩阵是否三列完整（概率×影响×可缓解性）？
- [ ] 关键观察指标是否区分了「确认 thesis」和「否定 thesis」？
- [ ] 核心结论是否有态度（非「有待观察」）？
- [ ] CLAUDE.md「竞对分析去伪存真六陷阱」：是否逐项过了一遍？
- [ ] CLAUDE.md「大厂入场压力测试」：是否覆盖？
- [ ] **P0 知识库沉积**：ind-res 完成后，必须写入 `concepts/[赛道名].md` + 更新 `overview.md`（CLAUDE.md §知识库规则-自动沉淀）。不可跳过。
