# 财务预测与回报测算

## 在体系中的位置

本 Skill 是 VC 投研 Agent 体系的 **Step 4**。详细关系定义见说明书 §1.2。

**启动前必须检查 4 项输入全部就绪**：

| # | 输入 | 来源 | 缺失时处理 |
|---|------|------|---------|
| ① | **公司历史财务数据** | `[项目名]/Datapack/财务/` 下财务相关原始资料（**必须**）| 如无，向用户索取 |
| ② | **公司未来财务预测假设** | 从 ind-res 和 comp-res 中抽象提取（**必须**）| 先检查 ind-res 和 comp-res 是否都已做完。如都做完→从中提取；如检查到其一没做→告诉用户哪个没做；如用户坚持不做→请用户直接提供财务预测假设 |
| ③ | **交易条款假设** | 直接询问用户（**必须**）| 投资金额、投后估值、后续融资假设等 |
| ④ | **可比估值分析** | 调用 comps skill（**必须**）| fin-mod 自行从 ind-res/comp-res 中提取行业赛道信息→交由 comps 搜索可比公司→用户确认→拉数→汇入 Valuation Sheet |

- **前置依赖**：`industry-research`（B：可比估值倍数、市场增速数据——**必需**，缺则告知用户可手动给假设）+ `company-research`（B：业务模型、收入驱动因素、单元经济数据——**必需**，缺则告知用户可手动给假设）
- **下游消费**：→ `ic-report`（B：回报结论 + 敏感性分析——缺则 ic-rep 对应章节标注缺口）
- **子模块关系**：**必须调用** `comps`（可比估值表——汇入 Valuation Sheet 作为退出估值基准）
- **外部 Skill 调用**：`wind-mcp-skill`（可比公司估值倍数、历史财务数据——comps 的底层数据源）
- **输出目录与文件命名**：本地 `[项目名]/财务/财务模型_v[N].xlsx`

## 版本管理规则

1. **每次运行生成新文件** — 输出文件命名 `财务模型_v[N].xlsx`，版本号自动递增（扫描 `财务/` 目录下已有文件，取最大版本号 +1）
2. **绝不覆盖旧版本** — v1、v2、v3... 全部保留，形成审计轨迹
3. **用户修改假设 → 生成新版本** — 用户对任何假设提出修改后，生成 v[N+1]，不在原文件上改
4. **版本号在脚本中硬编码** — 生成脚本的 `output_path` 中明确写出目标版本号

## 角色

服务于 VC 投资团队的财务建模分析师。核心任务：从 ind-res 和 comp-res 中提取量化假设 → 搭建利润表预测模型 → 对标可比公司做退出估值 → 计算我方投资回报（MoC/IRR）→ 敏感性分析 → 生成 Excel 模型文件。

## 必须向用户确认的交互点

以下是在 fin-mod 运行过程中**必须暂停并向用户提问**的节点。不得自行假设或跳过。

### A. 交易结构（搭建 Return Sheet 前必须确认）

**一次性提问模板**：

> "请确认本次交易核心参数：投资时点、本轮投后估值、我方投资额、总融资额、退出年限（默认5年）"

**退出年份自动计算**：投资年 + 退出年限，无需反问用户。

**后续融资稀释——按项目阶段自动判断（默认值）**：

| 项目阶段 | 默认后续融资轮数 | 默认每轮稀释 | IPO 稀释 | 判断依据 |
|---------|:---:|:---:|:---:|------|
| 早期（种子/A 轮） | 3 轮 | 10% | 25% | 投后估值 <10 亿，收入 <5,000 万 |
| 成长期（B/C 轮） | 1 轮 | 20% | 25% | 投后估值 10-50 亿，有一定收入规模 |
| Pre-IPO（D 轮+） | 0 轮 | — | 25% | 已接近上市条件 |

> 如用户给出了具体的稀释假设，以用户说的为准，覆盖默认值。无需每次反问。

### B. 可比公司选择（拉 Wind 数据前必须确认）

1. 从 ind-res/comp-res 中提取可比公司列表，补充行业知识中的相关上市公司
2. **展示给用户**：列出候选可比公司（代码 + 公司名 + 选择理由）
3. **提问**："这些可否作为可比公司？有没有需要补充或剔除的？"
4. 用户确认后再拉 Wind 数据
5. Wind 数据拉完后，按规则筛选（PE>200x 剔除 / PE<0 剔除 / PS>100 剔除），被剔除公司保留在表中但标红

### C. 退出倍数假设（完成可比公司分析后确认）

1. 判断退出年是否有净利润：
   - **有净利润（净利率>5%）→ PE 估值**：向用户展示可比公司 PE 中位数 → "可比公司 XX年 PE 中位数 ~XXx，退出年取 XXx（向下取整），可以吗？"
   - **无净利润/亏损 → PS 估值**：向用户展示可比公司 PS 中位数 → "可比公司 XX年 PS 中位数 ~XXx，退出年取 XXx（向下取整），可以吗？"
2. 未被采用的方法（PS 或 PE）作为交叉参考一并展示在模型中

### D. 关键假设修改窗口（模型生成后）

模型生成后**必须告知用户**：
> "模型 v[N] 已生成。如需修改任何假设（销量/价格/成本/费率/退出倍数/交易结构/稀释轮数等），请告知具体改动，我将生成 v[N+1]。"

用户修改假设后 → 更新对应蓝色单元格 → 生成新版本文件（见「模型修改与迭代」）。

## 核心原则

1. **假设显性化与可追溯** — 每个预测假设必须写清楚来源（来自 ind-res/comp-res/管理层/自行判断）和逻辑，不在单元格里「拍数」。**P&L 最右侧设注释列，逐行写预测逻辑与数据来源**（注释列位置 = 预测数据最后一列的右边一列，如预测到 J 列则注释列为 K 列）
2. **Bottom-Up 为主，Top-Down Cross-Check** — 收入预测以分产品线 Bottom-Up（量×价）为基本方法，用 Top-Down（市场规模×市占率）交叉验证；差异>20% 需解释
3. **保守优于乐观** — 当管理层声称与行业基准冲突时，向保守方向调整并在模型注释列中标注偏差
4. **颜色编码强制规范** — 🔵 蓝色 = 手工假设 | 🟡 黄色 = 历史数据（硬编码） | 🟢 绿色 = 公式计算。每个 Sheet 第一行标注颜色含义
5. **可比公司选择有纪律** — 同行业 + 相似商业模式。筛选规则按指标独立判断，非按公司整体剔除：PE<0（亏损）→ 该公司 PE 不算入均值；PE>200x → PE 不算入；PS>100x → PS 不算入。但该公司仍在表中保留（其他有效指标仍参与计算）
6. **退出估值方法匹配盈利状态** — 有稳定净利润（净利率>5% 且为正）→ PE 估值；无净利润/亏损 → PS 估值；重资产行业补充 EV/EBITDA
7. **IS → BS → CFS 顺序不可逆** — 先做利润表（v0.2.0），再做资产负债表，最后做现金流量表
8. **跨 Sheet 引用用单引号包裹含特殊字符的 Sheet 名** — `='P&L'!J29` 而非 `=P&L!J29`（`&` 是 Excel 特殊字符，不包裹会被误解析为 `@` 隐式交集运算符）
9. **注释文字不以 `=` 开头** — Excel 会将首字符为 `=` 的单元格内容当成公式解析，导致 `#NAME?` 错误。注释去掉前导 `=` 号

## 工作流程

### 第〇步：扫描前置输入

> **版本管理**：读取 ind-res/comp-res 产出时只取最高版本号的文件（如 `-v3` 优于 `-v2`），不加载旧版本。读取前先 `ls` 目录确认最新版本文件名。

0.1 读取 `.project-state.md`，了解项目整体进度和待验证假设

0.2 从 ind-res 产出中提取：

| 提取内容 | 对 fin-mod 的作用 |
|---------|------------|
| 可比公司列表及估值倍数（PS/PE） | 退出估值对标 |
| 市场规模与增速（TAM/SAM/SOM） | Top-Down Cross-Check |
| 行业毛利率/费用率/净利率基准 | 预测合理性校验 |
| KSF 中的规模/成本相关因素 | 成本预测逻辑参考 |

0.3 从 comp-res 产出中提取（**先读 comp-res 报告，再决定需要从原始文件补充什么**）：

comp-res 产出中可直接复用的结构化数据：

| comp-res 章节 | 可直接复用的内容 | 对 fin-mod 的作用 |
|---------|----------------|------------|
| §6.1 历史融资记录 | 轮次/时间/金额/估值/投资方（标准化表格） | 稀释模型输入 |
| 维度 1 商业模式 | 收费方式（订阅/项目/硬件/混合）、毛利率结构 | 决定收入预测方法 |
| 维度 1 TAM→SAM→SOM 模型 | 分行业×分年度的市场空间自建模 | Top-Down Cross-Check |
| 维度 4 客户结构 | 已签约客户、收入分布、Top 1/5 占比 | 收入质量判断 |
| §6.4 估值分析 | 可比公司线索、本轮估值逻辑 | 退出估值对标参考 |
| §6.3 财务基本面 | 收入量级、毛利率、费用结构的定性判断 | 预测合理性校验 |

以下 fin-mod 需要的数据 comp-res **不提供结构化提取**，需从原始 data pack 补充：

| fin-mod 需要 | comp-res 的覆盖程度 | 为什么不能直接用 comp-res |
|---------|------------|-------------------|
| 产品线量×价拆分 | comp-res 维度 2 分析产品形态和竞争力，不拆分每条产品线的单价和出货量 | comp-res 是定性分析，fin-mod 需要结构化数字 |
| 历史三表数字（IS/BS/CFS） | comp-res §6.3 只给「收入量级、毛利率」等定性判断 | comp-res 不给逐年的结构化三表数据 |
| 管理层具体预测数字 | comp-res §6.3 评估「BP 预测是否自洽」，不逐项提取增速/价格/成本的具体数字 | comp-res 是评估合理性，fin-mod 需要具体数值做假设基准 |

0.4 **定向扫描原始财务文件**（仅补充 comp-res 未覆盖的 3 项）：

这是 fin-mod 历史数据的**唯一权威来源**。在 `[项目名]/Datapack/财务/` 及相关子目录中**定向查找**（只找 comp-res 未覆盖的 3 项：产品线量价、历史三表、管理层预测数字）：

| 文件类型 | 查找内容 | 处理方式 |
|---------|---------|---------|
| 历史财务报表（Excel） | IS/BS/CFS 逐年数字 | 直接提取历史年份收入/成本/费用/净利润（comp-res §6.3 只给了定性判断，这里要具体数字） |
| 审计报告（PDF） | 经审计的财务数据 | **未加密**：先检查同目录下是否存在 `同名（转）.md` 缓存；如无则用 `pdf-converter` 提取（保存为 `原文件名（转）.md`）。**加密**：询问用户密码 → `qpdf --password=密码 input.pdf decrypted.pdf` → 解密后按未加密流程处理 |
| 财务预测表格（Excel/PDF） | 公司自己做的预测模型 | Excel 直接读取管理层预测的具体增速/价格/成本数字；PDF 同样走缓存→未加密/加密流程 |
| BP 中的财务章节（如有） | 管理层财务预测 | 作为假设参考，标注「管理层声称」（⚠️ BP 中通常无完整财务章节，以 Datapack/财务/ 中的 data pack 为准） |

> ⚠️ **无历史财务数据时**：向用户发出 warning，告知「公司 data pack 中未找到历史财务数据，模型的基期数据缺失」，请用户补充。
>
> ❌ **Wind 不用于拉取未上市公司财务数据**。Wind 只能拉到已上市公司的公开财务数据（仅用于第五步可比公司分析）。未上市公司的历史财务数据必须来自公司提供的 data pack，不能通过 Wind 获取。

0.5 与用户确认（按顺序，不可跳过）：

**a) 预测期长度**：
- 根据退出年份确定预测期。如 2025 年 6 月投资、2030 年 6 月退出 → 预测期 2025E–2030E（6 年）
- 默认退出年 = 投资年 + 5 年，无需反问用户年份

**b) 交易结构**（详见「必须向用户确认的交互点 §A」）：
- 一次性提问：投资时点/投后估值/本轮总融资额/我方投资额/退出年限
- 后续融资稀释按项目阶段自动判断默认值，用户有具体假设则覆盖

**c) 可比公司**（详见「必须向用户确认的交互点 §B」）：
- 从 ind-res/comp-res 提取候选可比公司列表 → 展示给用户确认 → 确认后再拉 Wind

### 第一步：搭建收入预测

1.1 确定产品/服务线清单（从 comp-res 提取）

1.2 为每条产品线选择预测方法：

| 业务类型 | 推荐方法 | 需要的假设 |
|---------|---------|----------|
| 硬件/制造业 | 销量 × 单价 | 销量增速、单价变化率 |
| SaaS/订阅 | 客户数 × ARPU | 客户增速、ARPU 变化率 |
| 项目制/服务 | 直接收入增长率 | 收入增速 |
| 电商/交易平台 | GMV × Take Rate | GMV 增速、Take Rate 变化 |

1.3 对每条产品线：
- 历史收入填入黄色单元格（D-F 列，2022-2024）
- 假设参数填入蓝色单元格（预测年份列，从投资年起至退出年）
- 预测收入用公式（绿色单元格）= 基期值 × (1 + 增长率) 或 量 × 价

1.4 Top-Down Cross-Check：
- 总市场规模 × 公司市占率 vs 加总产品线收入
- 差异 >20%：回到假设调整，或给出合理解释

1.5 管理层声称 Cross-Check：
- 标注管理层对收入的指引（如「2026 年收入 100 亿」）
- 模型预测与管理层指引的偏差及原因

### 第二步：搭建成本与毛利

2.1 对每条产品线确定成本预测方法：

| 方法 | 适用场景 | 需要的假设 |
|------|---------|----------|
| 单位成本法 | 有量价模型时 | 单位成本变化率 |
| 毛利率法 | 无销量拆分时 | 毛利率变化路径 |

2.2 对每条产品线：
- 历史 COGS/单位成本填入黄色单元格
- 假设参数（单位成本变化率 或 毛利率）填入蓝色单元格
- 预测 COGS 和毛利用公式（绿色）

2.3 Cross-Check 毛利率 vs 行业水平：
- 公司整体毛利率 vs ind-res 中的行业毛利率区间
- 偏差 >10pp 需解释（产品结构差异 / 规模效应 / 技术溢价）

### 第三步：搭建运营费用

3.1 费用科目及预测方法：

| 费用科目 | 预测方法 | 备注 |
|---------|---------|------|
| 税金及附加 | 历史平均比率 × 营收 | 取过去 3 年均值 |
| 销售费用 | 费用率 × 营收，规模效应递减 | 默认每年 ×0.9 |
| 管理费用 | 费用率 × 营收，规模效应递减 | 默认每年 ×0.85 |
| 研发费用 | 费用率 × 营收 或 绝对值假设 | 早期公司可能保持高绝对值 |
| 财务费用 | 暂时简化处理（v0.1.0） | 标注「需 BS 完整预测」 |
| 资产减值损失 | 历史趋势外推 | 通常大幅收缩 |
| 其他收益/损失 | 保守假设为 0 | 除非有明确预期 |

3.2 费用率趋势：
- 历史费用率填入黄色单元格
- 未来费用率假设填入蓝色单元格
- 费用金额用公式 = 费用率 × 营收（绿色）

3.3 其他关键假设（蓝色单元格）：
- 所得税税率（参考历史有效税率或法定税率）
- 少数股东损益占比（参考历史或设为 0）
- 不分红假设（早期公司默认）

### 第四步：完成利润表

4.1 核心公式链（全部绿色单元格）：

```
营业收入 = Σ 产品线收入
营业成本 = Σ 产品线 COGS（或 = 营收 - 毛利润）
毛利润 = 营业收入 - 营业成本
营业利润 = 毛利润 - 税金 - 销售费用 - 管理费用 - 研发费用 - 财务费用 + 其他收益净额
利润总额 = 营业利润 + 营业外收入 - 营业外支出
所得税 = IF(利润总额>0, 利润总额×税率, 0)
净利润 = 利润总额 - 所得税
归母净利润 = 净利润 - 少数股东损益
EBIT = 净利润 + 所得税 + 财务费用
EBITDA = EBIT + 折旧 + 摊销
```

4.2 关键比率（全部绿色单元格）：
- 营业收入增长率 = 当期/上期 - 1
- 毛利率 = 1 - 营业成本/营业收入
- 营业利润率 = 营业利润/营业收入
- 净利率 = 净利润/营业收入
- EBITDA% = EBITDA/营业收入

### 第五步：可比公司分析与退出估值

> **本步骤核心方法论已独立为子模块 [`comps`](../comps/SKILL.md)**，支持三种模式（指定公司/指定赛道/混合），可独立触发也可嵌入 fin-mod 调用。以下保留 fin-mod 的集成流程，详细 Wind 调用、筛选规则、倍数计算方法见子模块。

5.1 从 ind-res 获取可比公司候选列表 → **先展示给用户确认**（见交互点 B）→ 确认后调用 `comps` 子模块拉取 Wind 数据并输出可比估值表。

5.2 从 `comps` 产出中提取：
- 可比公司估值表（PS/PE 各年度、中位数、平均数）
- 筛选说明（被剔除公司及原因）
- 推荐退出倍数（向下取整后的中位数）

5.3 退出估值（fin-mod 集成）：
- 如预测期最后一年有稳定净利润（净利率>5% 且为正）→ 采用 PE 估值为主、PS 交叉参考
- 如无净利润/亏损 → 采用 PS 估值为主
- 退出估值 = 预测净利润 × 退出 PE（或 预测收入 × 退出 PS）
- 向用户确认采用的退出倍数（见交互点 C）
- 逐年递减：退出年更远 → 倍数更低

5.4 敏感性分析（双因素，fin-mod 生成）：
- 因素 1：预测净利润 ±15%
- 因素 2：退出 PE 倍数 20x / 22.5x / 25x / 27.5x / 30x

### 第六步：回报测算

6.1 交易结构（全部通过交互点 A 向用户确认）：

| 参数 | 公式/来源 | 示例 |
|------|----------|------|
| 投资时点 | 用户提供 | 2025-06-30 |
| 退出时点 | 用户提供（默认 +5 年） | 2030-06-30 |
| 投后估值 | 用户提供 | 5.00 亿 |
| 本轮总融资额 | 用户提供 | 1.00 亿 |
| 投前估值 | = 投后 - 本轮融资额 | 4.00 亿 |
| 我方投资额 | 用户提供 | 0.50 亿 |
| 本轮进入持股 | = 我方投资额 / 投后估值 | 10.00% |

6.2 稀释模型（v0.2.0 支持多轮融资）：

**早期项目必须考虑多轮稀释**。

```
后续融资轮数（n）= 用户确认（如 3 轮）
每轮稀释比例（d）= 用户确认（如 10%/轮）
IPO 稀释比例（d_ipo）= 用户确认（如 25%）

IPO 前持股 = 进入持股 × (1 - d)^n
IPO 后持股（退出时）= IPO 前持股 × (1 - d_ipo)
```

示例：进入 10% → B 轮 9.0% → C 轮 8.1% → D 轮 7.29% → IPO 后 **5.47%**

**在 Return Sheet 中展示稀释路径一览表**：
| 轮次 | 稀释比例 | 剩余持股 |
|------|:---:|:---:|
| 本轮 | — | 10.00% |
| 本轮后上市前第一轮 | 10% | 9.00% |
| 本轮后上市前第二轮 | 10% | 8.10% |
| 本轮后上市前第三轮 | 10% | 7.29% |
| IPO | 25% | **5.47%** |

6.3 退出收益：
```
退出估值 = 2030E 净利润 × 退出 PE（或 2030E 收入 × 退出 PS）
我方持股退出价值（毛） = 退出估值 × IPO 后持股比例
退出税费 = 毛退出价值 × 退出税费率（默认 3%）
我方退出价值（净） = 毛退出价值 - 退出税费
```

> **退出税费**：退出时需扣除交易佣金、印花税、过户费等摩擦成本，默认假设 3%。MoC 和 IRR 均基于**净退出价值**计算。

6.4 回报指标：
```
净现金流：
  - 投资时点：-我方投资额
  - 退出时点：+我方退出价值（净）

MoC = 净退出价值 / 投资额
IRR = XIRR(现金流数组, 日期数组)
持有年限 = (退出日 - 投资日) / 365
```

6.5 敏感性分析（双因素）：
- 因素 1：退出净利润 ±15%（0.85x / 0.90x / 1.00x / 1.10x / 1.15x）
- 因素 2：退出 PE 倍数 20x / 22.5x / 25x / 27.5x / 30x
- **IRR 和 MoC 均扣除了 3% 退出税费**
- **IRR 和 MoC 各做一张敏感性表**
- IRR 公式（简化）= `((净利润 × PE × 持股%) / 投资)^(1/年数) - 1`
- MoC 公式 = `净利润 × PE × 持股% / 投资`

## 模型修改与迭代

fin-mod 模型生成后，用户可能会对假设提出修改。这是正常的设计迭代流程。

### 迭代触发

用户对以下任何内容提出修改时，触发迭代：
- 销量/价格/成本/费用率等 P&L 假设
- 可比公司选择（增加/剔除）
- 退出倍数（PE/PS）
- 交易结构（投资额/估值/融资轮数/稀释比例）
- 退出年份

### 迭代流程

1. **用户提出修改** → 确认具体改动内容（哪个单元格、从 X 改成 Y、理由）
2. **更新对应蓝色单元格** → 保持所有公式不变
3. **生成新版本文件** → `v[N+1]`，不覆盖旧版本
4. **简要告知改动** → "v3 相比 v2：将 2030E 销量从 30,000 台上调至 35,000 台，原因是 XXX"
5. **如果改动影响结论** → 在 Excel 注释列中标注改动原因和影响

### 用户修改窗口提示

模型首次生成后，**必须**主动告知用户：

> "模型 v[N] 已生成。如需修改任何假设（销量/价格/成本/费率/退出倍数/交易结构/稀释轮数等），请告知具体改动，我将生成 v[N+1]。旧版本保留不覆盖。"

### 数字格式

```python
# 金额（亿元）：'#,##0.00'
# 金额（万元）：'#,##0'
# 百分比：'0.00%'
# 倍数：'0.0"x"'（PS/PE/MoC 等所有估值倍数必须带 x 后缀）
# 股数（万股）：'#,##0.00'
# 日期：'YYYY-MM-DD'
```

### 跨 Sheet 引用规范

- **含特殊字符的 Sheet 名必须用单引号包裹**：`='P&L'!J29/10000` 而非 `=P&L!J29/10000`
  - `&` 是 Excel 公式中的连接运算符，不包裹会被误解析为 `@`（隐式交集运算符）
  - 安全做法：所有跨 Sheet 引用一律加单引号
- **注释单元格不以 `=` 开头**：Excel 将以 `=` 开头的单元格内容当作公式解析
  - ❌ `= 净利润 ÷ 营业收入` → `#NAME?`
  - ✅ `净利润 ÷ 营业收入`
  - ✅ `'= 净利润 ÷ 营业收入`（前置单引号强制文本模式）

### 其他格式

- 表头行冻结（freeze_panes）：P&L 和 Return Sheet 设置冻结窗格；Valuation Sheet **不冻结**
- P&L 注释列（最右侧列）宽度 ≥ 42 字符
- 公式单元格锁定（protection），假设和历史单元格可编辑
- 边框：表头和数据区加细线边框
- 被剔除可比公司行标红底色（`F4B4C2`），字体缩小（9pt）

## 异常场景处理

| 场景 | 处理 |
|------|------|
| comp-res/ind-res 中无足够的量化数据 | 列出缺失数据清单，请用户补充后再启动 fin-mod |
| 公司 data pack 中无历史财务数据 | ⚠️ Warning 用户：「data pack 中未找到历史财务数据，模型基期缺失」，请用户补充。注：先检查 comp-res §6.3 是否已有财务定性数据 |
| 公司 data pack 中有财务预测表格 | 提取管理层预测的具体增速/价格/成本数字 → 与 comp-res §6.3 的合理性评估对照 → 向用户说明是直接 take 还是打折 |
| Wind 2025E 一致预期返回空（仅用于可比上市公司） | 用 2024A + 2026E 取 CAGR 估算 2025E，或直接用 2025A 实际数据（如已过期） |
| 可比公司不足 3 家 | 放宽行业范围（上下游），标注「可比公司样本有限」 |
| 公司无产品线拆分 | 用整体收入增长率预测，标注「无产品线拆分，使用整体增速法」。注：先检查 comp-res 维度 2 是否有产品形态信息可辅助拆解 |
| 预测期首年仍在严重亏损 | 仍用 PS 估值，标注切换 PE 的条件和时点 |
| 管理层声称与行业基准严重冲突 | 保留管理层版本作为乐观情景，模型采用保守版本作为基准 |
| 用户不提供交易条款 | 跳过 Return Sheet，仅产出 IS + Valuation，标注「待补充交易条款」 |
| 用户未确认可比公司 | 暂停，等待用户确认后再拉 Wind（不得自行假设可比列表） |
| Wind API 调用失败 | 重试 1 次，仍失败则用 comp-res/ind-res 中的静态倍数数据，标注「Wind 数据不可用，使用报告数据」 |
| 毛利率 >100% 或 <0 / 费用率 >100% | ⚠️ 不是错误但发出警报，标注「异常值，请检查假设」，可能是首年营收极低导致的高费用率或亏损期负毛利率 |
