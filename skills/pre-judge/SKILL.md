# 项目初筛 Skill

## 角色

拿到 BP/材料后快速判断值不值得深看。不是 mini 版尽调，是**方向性判断**——这个赛道对不对、这个团队对不对、最大的坑在哪。

## 核心原则

1. **先给判断再展开**：一句话结论放在最前面
2. **亮点和风险都要有**：不自嗨也不过度保守
3. **必须有下一步**：Go/No Go/Conditional Go + 具体条件
4. **不读 DD 底稿**：过滤标记的缴款凭证/工商档案等不主动读取

## 前置依赖
- 无硬依赖
- 首次接触项目时，先执行 Ingest（见 `docs/INGEST.md`）或确认用户已提供足够材料

## 工作流程


**项目上下文重置（防串项目）**：开始撰写前，确认当前项目名称。报告中所有案例/竞品/数据/人名必须来自当前项目。不可复用上一项目的分析框架作为模板代入。

### 材料检查（强制）
研究前扫描项目下所有已有访谈（见闻录 + 本地访谈文件）。访谈是最高质量的一手信息——必须逐份检查是否有可用素材，不可仅依赖 BP/Datapack。

### 第一步：材料扫描
- 读 BP + Datapack 关键文件
- 读 Master 中「参考资料」节的精选文章
- WebSearch：公司融资/团队/竞品/行业动态

### 第二步：五个维度速评
- 公司概况（一句话定义 + 关键事实表）
- 团队速评（创始人深度画像：学术/产业轨迹+量化成绩+做成过什么+短边。核心团队互补矩阵。如果「为什么是他」回答不了，标注为管访待验证）
- 技术速评（路线正确性 + 竞争壁垒 + 天花板）
- 市场与客户（客户质量 + 赛道增速 + 竞争位置）
- 融资与估值（历史 + 本轮 + 老股东信号）

### 第三步：判断

**硬伤检查（在 Go/No Go 之前强制执行）**：以下六项逐条扫描。不适用→跳过。触发→升级为 P0 必须核实（管访对质/法务确认/客户访谈），核实后仍存疑→No Go。不是自动否决——是「这件事必须查清楚才能往下走」。

1. 创始人诚信存疑（前后说法不一致/刻意回避关键问题）
2. 股权代持/质押未清理（影响上市合规）
3. 知识产权归属不清（职务发明纠纷/前雇主 IP 风险）
4. 客户/供应链集中度过高（单客户 >50% 且无替代方案 / 核心环节卡脖子且无国产替代）
5. 数据合规/监管存在硬伤
6. 融资造假（PR 融资额 vs 工商实缴严重不符）

**通过硬伤检查后**：
- Go / Conditional Go / No Go
- 明确条件（管访验证X / 客户尽调Y）
- 建议下一步（pre-judge → ind-res → comp-res 路径）
- **投资逻辑必须是因果链**：5 条之间必须有「因为 A，所以 B；因为 B，所以 C」的递进关系。写完测试：抽掉中间一条，整个逻辑链是否断裂→断裂的条是凑数的，应合并或删除。最后一句必须是「投的不是 X，是 X→Y→Z 递进咬合的系统性确定性」。不是「亮点列表」
- 风险项一一对应投资逻辑中的假设。哪条逻辑最脆弱→对应哪个风险最大
- 创始人必须有「做成过什么」。不只是履历——具体的产品/项目/出货量/论文

### 教育优先节（强制）
在「一句话判断」和主体分析之间，必须插入「行业/技术基础」节。200-400 字，白话+类比。必须回答：①这个行业在解决什么物理问题？②有哪几种不同的做法（技术路线）？③为什么标的选的这条路更好？判断标准：拿给高中生看，能说清楚。

## 输出结构

```markdown
# [公司] 初筛报告 v[N]

> 版本说明行：标注本版基于哪些材料、vs 上一版的增量变化。

## 行业/技术基础
（强制。教育优先——白话讲清三件事。200-400字。）

## 一句话判断
（Go / Conditional Go / No Go + 一句话理由。如果是 Conditional Go，标注方向箭头 ↑↓ 表示确定性方向。）

## 1. 公司概况
（强制表格。如果是 v2+ 更新版，采用双列对比格式：

| 维度 | v1 | 🆕 v2增量 |
|------|-----|------|

v1 首次创建时用单列表格：

| 维度 | 内容 |
|------|------|
| 公司 | 全称+英文名 |
| CEO | 姓名+国籍+学历 |
| 定位 | 一句话 |
| 产品线/验证 | 在售或在研产品+量产/验证状态 |
| 团队 | 规模+核心骨干 |
| 融资 | 轮次+金额+估值）

## 2. 团队速评
（不是简历搬运——回答「为什么是他」。「做成过什么」必须有具体数字/产品/项目。短边必须指出。如果是 v2 更新，标注 🆕 新增判断和来源。）

## 3. 技术速评
（路线正确性 + 差异化 + 天花板。如果是 v2 更新且软件/生态是新识别出的瓶颈，单独展开分析。）

## 4. 🆕 核心变化（v2+ 专属——如适用）
（自上一版以来的关键增量信号。如果涉及客户验证，用正面/负面双列表格：

| 维度 | 正面 | 负面 |
|------|------|------|
| [维度1] | [信号] | [信号] |
| … | | |

表后跟综合判断——不是各打五十大板，是给出结论：这些正负面信号加总后，确定性是上升还是下降。）

## 5. 市场与客户
（客户质量+赛道增速+竞争位置。如有客户pipeline，用表格：客户/场景/进展/确定性评分。确定性用 ⭐ 1-5。）

## 6. 竞争定位
（不是竞品名单——是差异化判断表：

| 竞对 | 状态 | 芯纪微 vs |
|------|:---:|------|
| [竞对A] | [关键数字/状态] | [一句话差异化] |

如果有一个维度的差距是碾压级的（如软件生态几十万开发者 vs 从零搭建），必须单独标注。）

## 7. 风险矩阵
（强制表格——每行包含风险+概率/严重度+变化趋势：

| 风险 | v1 | 🆕 v2（如适用）|
|------|:---:|:---:|
| [风险1] | 🔴/🟡 | 🔴/🟡（变化原因）|

至少 4 项风险。P0 级风险必须标注为 🔴。）

## 8. 投资判断
（不是重复一句话判断——是完整的投资逻辑段落。包含：①确定性方向 ②关键条件 ③窗口期判断。）

## 建议下一步
（按 P0/P1 优先级列出。每条必须可执行——不是「了解行业」，是「要求公司提供软件工具链roadmap，具体到算子支持/编译工具/模型转换的时间表」。至少 3 条。）

## 关键数据速查
（一张表：指标 / 数值 / 来源。强制附录。）

## 信息来源
（精简表格：来源 | 类型 | 关键内容）
```

## 输出后自检（强制）

完稿前逐项确认：
- [ ] 「行业/技术基础」节是否用白话讲清了？（高中生测试）
- [ ] 风险矩阵是否 ≥4 项？P0 是否标注为 🔴？
- [ ] 如果涉及客户验证信号（v2+），正面/负面是否对等呈现而非选择性引用？
- [ ] 投资判断是否说清楚了「投的不是 X，是 X→Y→Z 递进咬合的系统性确定性」？
- [ ] 下一步是否具体可执行（有对象/有动作/有时间节点）？
- [ ] 关键数据速查表是否每行有来源？
- [ ] CLAUDE.md「竞对分析去伪存真六陷阱」：创始人自我定位偏差/竞对数据注水/投资方互相美言/样本偏差/静态对比/战略选择vs技术难——是否都过了一遍？
- [ ] CLAUDE.md「大厂入场压力测试」四个必答题是否覆盖？（嵌入在竞争定位或风险分析中）

## 来源可靠性（通用规则）

关键数据标注来源类型：✅多源验证 / ⚠️公司自述（未独立验证）/ 💭推断。公司自述的BP/IC memo/管理层数据不可作为事实引用。
