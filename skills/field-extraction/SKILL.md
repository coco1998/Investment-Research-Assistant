# 会议字段提取技能

从 ASR 转录稿或会议纪要中提取结构化元数据，输出为 JSON 格式，用于写入 Notion 见闻录数据库。

## 输入

- ASR 转录稿全文（或已生成的会议纪要）
- 可选的已知信息（如已知日期、已知公司名等）

## 输出字段

按以下 JSON 格式输出，所有字段必填（不确定的值用空字符串或空数组）：

```json
{
  "title": "被访谈人公司+姓名/身份标识",
  "date": "2026-05-14",
  "role": "行业专家",
  "meeting_type": "专家访谈",
  "sectors": ["AI大模型", "开源"],
  "summary": "一句话概括会议核心内容",
  "key_info": [
    "关键信息点1",
    "关键信息点2",
    "关键信息点3"
  ],
  "company": "公司名（可选，不填则从 title 自动拆分）",
  "position": "职位（可选，不填则从 title 自动拆分）"
}
```

## 各字段提取规则

### title（公司+职位）
- 格式：`公司名-身份/姓名` 或 `主题-专家来源`
- 专家访谈：提取专家所在公司/机构 + 姓名/身份，如 `高临-DeepSeek V4专家`
- 公司交流：提取被访谈公司名 + 访谈对象职位，如 `Example Sensor-创始人`
- 如果转录稿中无明确信息，从内容推断最合适的标题
- 这是 Notion 的 title 字段，用于列表展示，要简洁有意义
- **注意**：Notion 中 title 属性名为「公司+职位」（非「公司+姓名」）
- **拆分规则**：`notion_uploader.py` 会自动按首个「-」拆分为「公司」和「职位」两列。含连字符的公司名（如 中国电信-TeleAI、某头部客户/OPPO/长存）整体归入公司列，纯后缀（如 -管理层访谈、-路演）自动去除

### company（公司）
- **可选字段**，不填则 `notion_uploader.py` 从 title 自动拆分
- 如需精确控制（如公司名含「-」），可显式指定

### position（职位）
- **可选字段**，不填则 `notion_uploader.py` 从 title 自动拆分
- 如需精确控制，可显式指定

### date（日期）
- 从转录稿中提取会议日期
- 格式：YYYY-MM-DD
- 如果转录稿标题或开头有时间戳，优先使用
- 找不到则用空字符串

### role（身份）
- 可选值（根据实际情况选择最贴切的）：
  - `行业专家` — 第三方行业专家/技术专家/产业链人士
  - `创业公司高管` — 创业公司创始人/CEO/管理层
  - `FA` — 财务顾问
  - `投资人` — 投资机构人士
- 专家访谈通常选「行业专家」
- 公司交流通常选「创业公司高管」

### meeting_type（会议类型）
- 可选值：
  - `专家访谈` — 与行业专家/产业链人士的访谈
  - `公司访谈` — 拜访/调研某家公司，与公司管理层交流
  - `coffee chat` — 非正式的闲聊/碰面
  - `饭局` — 饭局交流
  - `内部会议` — 内部讨论会
- 根据转录稿内容和形式判断

### sectors（赛道标签）
- 1 到多个标签，用数组表示
- 标签应简洁，1-6 个字
- 从会议内容中提取核心赛道/行业
- 示例：`["AI大模型", "算力芯片"]`、`["具身智能", "3D视觉"]`、`["SaaS", "金融科技"]`
- 不要过于宽泛（如"科技"），也不要过于细节
- 如果涉及多个赛道，都列出来

### summary（一句话摘要）

目标：**直戳本质，一句话讲清楚这场会的核心价值**。阅读者看完这句话就知道值不值得点进去读全文。

要求：
- 40-80 字，一句话
- 必须包含：讨论对象 + 核心判断/结论 + 关键量化信息（如有）
- 不是"讨论了A、B、C话题"，而是"关于A得出X结论，B的判断是Y"
- 有观点就说观点，有数据就说数据，不要写"分析了""探讨了""涉及了"这类虚词
- 如果专家给出了明确的投资判断或排位，直接点出来

好的例子：
- `DeepSeek V4本质是补课而非颠覆，核心技术无原创性，打开思考模式后TOKEN成本是竞品4倍以上，市场反馈平淡`
- `MiniMax独有MTB技术提效30%且3年可回收硬件成本，是唯一算得过账的大模型公司；智谱产品化强但项目亏损5年收不回本`

差的例子：
- ❌ `围绕DeepSeek V4的技术路线、定价策略和产业链影响展开讨论分析`（什么都没说）
- ❌ `专家深度分析了国产AI芯片的产品进度与竞争格局`（没有实质结论）

### key_info（关键信息）

目标：**全文最关键的判断/数据/结论，每条都能独立站住脚**。这 3 条信息应该是你在会后跟同事转述时会最先说的事。

要求：
- 最多 3 条，每条 30-70 字
- 每条必须包含一个**可被引用的结论**或**可被验证的数据**
- 不是 topic heading，而是带判断的完整陈述句
- 宁缺毋滥：如果只有 1-2 个真正重要的点，就只写 1-2 条
- 优先选择：反直觉的判断、有争议的结论、独家的数据、明确的排名/选优
- 各条之间不要重复，覆盖不同维度

好的例子：
- `华为950年内无法量产（2027 Q2-Q3），昆仑芯供应链最稳——李彦宏4月去三星买断58万颗产能，腾讯已下单近20万片`
- `MiniMax独有MTB技术可使解码效率提升30%但不对外开放，TOKEN成本比智谱低60%，是唯一3-3.5年可回收硬件成本的大模型公司`

差的例子：
- ❌ `详细分析了国产AI芯片各家厂商的产品和出货情况`（没有具体结论）
- ❌ `DeepSeek V4是一个重要的模型发布`（空洞）

## 判断逻辑

1. 先判断会议类型：如果主要是专家在分析行业/产品/技术 → 专家访谈；如果主要是公司在介绍自身业务 → 公司访谈
2. 根据会议类型推断身份：专家访谈 → 行业专家；公司交流 → 创业公司高管
3. 赛道从讨论主题中提取，覆盖会议涉及的主要行业方向
4. 摘要和关键信息需在会议纪要生成后提取，确保准确性

## 注意事项

- 不要在输出中包含转录稿原文或大段引用
- 不要输出 JSON 以外的内容
- 如果转录稿质量差、信息不全，在 JSON 中留空而非猜测
- 日期格式必须严格为 YYYY-MM-DD
