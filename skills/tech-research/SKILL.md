# 技术研读 Skill

## 在体系中的位置

独立触发或被 ind-res 调用。路径/规则见 CLAUDE.md。

## 角色

技术路线研判——不是罗列技术名词，而是回答：**这条路线为什么是正确/错误的选择？壁垒有多深？天花板在哪？**

## 核心原则

1. **技术路线强制推导**：原理→本质优势→现状瓶颈→难点→KSF→投资判断
2. **竞对技术对比引用 comp-ana**：技术路线对比表从 comp-ana 数据文件提取，不手写
3. **不回避天花板**：每条路线必须明确「当前能做到什么、永远做不到什么」
4. **源头可追溯**：学术论文/专利/专家访谈/公司DP，标注来源

## 前置依赖
- 无硬依赖（可独立触发）
- 被 ind-res 调用时：接收 ind-res 的赛道定义和技术关键词
- 竞对技术对比 → 引用 comp-ana 数据文件

## 工作流程


**项目上下文重置（防串项目）**：开始撰写前，确认当前项目名称。报告中所有案例/竞品/数据/人名必须来自当前项目。不可复用上一项目的分析框架作为模板代入。

### 材料检查（强制）
研究前扫描项目下所有已有访谈（见闻录 + 本地访谈文件）。访谈是最高质量的一手信息——必须逐份检查是否有可用素材，不可仅依赖 BP/Datapack。

### 第一步：技术定位
- 确认研究对象（公司/赛道/技术路线）
- **先执行领域自主学习检索（强制）**：①结构检索——「[技术名] 分类/技术路线对比/产业链」→建立技术分类树。②标准检索——「[技术名] 核心指标/评测标准/benchmark」→理解这个技术领域用什么指标衡量好坏。结果写入报告。详见 CLAUDE.md「领域自主学习原则」
- 检索知识库已有技术分析（`知识库/2_wiki/`）

### 第二步：技术路线深度分析
- **分层递进**（不可跳过）：大类→子类→具体路线→材料/算法层面。每层论证「为什么这条分支更重要」
- 原理（一层物理/数学本质）
- 发展历程（关键节点时间线+行业转折点。含技术周期阶段命名，如「2027-29规模化导入期」）
- **学术溯源**（创始人核心论文×3+）
- 核心组成（子模块拆解+功能+技术实现）
- 优劣势量化对比：每项对比至少1个数字。不只比参数——**成本结构拆解（当标的宣称成本优势时强制）**：逐项拆解成本驱动因素（具体项根据行业确定——制造看材料/设备/人员/洁净室/折旧，AI 看算力/数据/带宽/训练轮次），每项和主要竞品路线逐项对比。区分**结构性优势**（技术路线决定的，不会随时间消失）vs **阶段性优势**（规模和良率决定的，竞品追得上）
- 技术瓶颈 → 推导 KSF（解决了什么难点→需要什么能力→谁具备）。每层壁垒至少1条量化证据
- 自检：概念框架 vs 工程对比？缺概念框架→管访后触发 v2

### 第三步：竞争技术对比
- 从 comp-ana 数据文件提取技术路线对比表
- 代际差距（用季度/产品代际衡量）
- **如 comp-ana 数据文件不存在**：自主构建技术路线对比。**强制覆盖维度**（不可少于以下 8 列）：技术路线 / 量产状态 / 最大算力 / 典型功耗 / 算法能力 / SOC集成 / 供应链 / 核心场景。每行至少填满 6 列——缺数据的标注 `[未知]` 并列入尽调清单

### 第四步：风险与投资含义
- 技术风险矩阵（路线/工程/执行×概率×影响）
- 投资含义（受益方/受损方/关键观察指标/时间判断）

## 输出后自检（强制）

完稿前逐项确认（不可跳过）：
- [ ] 「关键技术概念」节是否用白话讲清楚了技术原理？（拿给高中生能看懂）
- [ ] 竞品技术对标表是否 ≥8 列 × ≥3 行？每格有数字或 `[未知]`？
- [ ] 技术壁垒评估是否分层排序（≥4个维度）？每层有具体证据？
- [ ] 技术风险矩阵是否 ≥5 项？区分了路线/公司/时序风险？
- [ ] DD 问题清单是否 ≥6 个具体问题？
- [ ] 信息来源表是否每行可追溯到具体文件/URL？
- [ ] CLAUDE.md「素材利用率问责」：回扫所有已读材料——有没有数字/原话/案例可以用但漏掉的？

## 来源可靠性（通用规则）

关键数据标注来源类型：✅多源验证 / ⚠️公司自述（未独立验证）/ 💭推断。公司自述的BP/IC memo/管理层数据不可作为事实引用。
