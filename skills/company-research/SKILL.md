# 公司深度尽调 Skill

## 在体系中的位置

Step 3。C 级硬依赖：pre-jdg + ind-res 必须完成。

## 六大维度

| 维度 | 核心问题 |
|------|------|
| **团队** | 创始人深度画像（≥300字：学术/产业轨迹+量化成绩+同行评价+短边）。全团队表格（每人的角色/背景/贡献）。阶段演进故事线（早期技术→中期商业→近期量产），不是静态罗列 |
| **技术** | 技术路线/壁垒深度/可持续性（引用 tech-research）。每层壁垒至少1条量化证据（数字/参数/成本/良率），不只定性描述 |
| **产品与市场** | 财务预测中出现的所有产品线均需独立卡片式描述（参数/形态/场景/差异化/互补关系），不可遗漏。产品不可仅用表格。**客户 pipeline 全景表（强制格式/5 列）**：客户名称/当前进展/订单量级+金额/产品特点/后续节奏。每家客户至少1行。客户必须分层归类（不只是列表），每类解读「为什么选你而不是竞品」。注：客户名称可脱敏（「某头部 AR 品牌」），但量级和进展必须具体 |
| **财务** | 收入拆到具体落地项目（不仅是产品线×客户类型）。至少5行数据表+3条关键财务观察。区分标品硬件/项目制/数据服务/框架协议四类订单 |
| **法务** | Cap Table/IP归属/竞业限制/合规风险 |
| **竞争** | 全行业梯队（龙头/海外学术/国内跟随/传统厂商），不仅限于直接竞对。提炼赛道 KSF，逐条对标公司能力 |

每个维度四段式：**事实**（来源标注：[事实-管访]/[事实-第三方]/[推断]/[假设]）→ **论证**（分析判断）→ **风险评估** → **待验证**。事实和观点必须分离。
- 投资逻辑必须是因果链：不是「因为X很重要+我们做X→所以我们好」，而是「因为X→所以必须解决Y→只有我们能解决Y→因此我们赢」。每条逻辑回答「为什么」
- 创始人画像必须回答：为什么是他而不是别人？竞对挖类似背景的人多久能复制？
- 访谈中有原话可用时优先用原话——创始人的表达比分析师的转述更有说服力。但未做深度管访前不强求
- 投资逻辑闭环：每条逻辑必须在正文有对应量化展开（数字+来源+推理）。读者可从开篇跳转到后文验证每一条
- 产品roadmap时间颗粒度：必须有年份+季度节点（如「2027Q2全彩量产」），不可用「在研」「规划中」模糊替代
- 客户分层+关系解读：客户必须分层归类（不只是列表），每类解读「为什么选你而不是竞品」。不只是客户需求——要解释「为什么客户的行为模式和组织特征决定了供应链选择」（大厂 KPI/风险偏好/组织惯性 vs 创业公司的生存压力和创新激励）
- 中长期预判：报告必须包含至少2个前瞻判断（技术路线收敛/竞争格局演变/产品迭代方向），不只写现状

## 工作流程


**项目上下文重置（防串项目）**：开始撰写前，确认当前项目名称。报告中所有案例/竞品/数据/人名必须来自当前项目。不可复用上一项目的分析框架作为模板代入。

### 材料检查（强制）
研究前扫描项目下所有已有访谈（见闻录 + 本地访谈文件）。访谈是最高质量的一手信息——必须逐份检查是否有可用素材，不可仅依赖 BP/Datapack。

### 第〇步：材料准备
- 读 pre-jdg + ind-res + tech-research + comp-ana
- 读所有见闻录（管访+专家+客户）
- 读 Master + BP + Datapack 已转换文件
- 利用 session 缓存：已读过的文件不重复

### 第一步：六维度逐一分析
- 每个维度：事实（来源标注）→ 观点论证 → 短边识别
- 事实和观点必须分离

### 第二步：综合判断
- 5条投资逻辑闭环（逻辑链完整，不能只说结论）
- 致命短板识别（P0，投前必须验证）
- 风险全矩阵（概率×影响×可缓解性）

### 第三步：下一步行动
- P0 必须搞清楚的问题
- P1 建议搞清楚的问题
- DD Request（书面材料优先）

| 端到端 | | | |

每格必须填——缺数据标注 [未知]。）

## 3. 技术
（引用 tech-research。如果 tech-research 已有深度分析，本节做投资维度综合判断——不重复技术细节，聚焦「这对投资意味着什么」。如果是v2更新且软件/生态是新识别出的关键维度，单独展开分层分析。）

### 4.2 商业化节奏（从0→1→N的路径和时间判断）

## 自检清单

- [ ] 致命短板是否诚实面对（不回避最核心风险）？
- [ ] 事实和观点是否分离（事实有来源标注，观点有推理链）？
- [ ] 客户pipeline表是否 ≥4行？每行有确定性评分？
- [ ] 产品竞品对比表是否 ≥4列 × ≥4行？每格有内容或 [未知]？
- [ ] 是否有「关键数据速查」附录？
- [ ] 是否有「信息来源」附录？

## 来源可靠性（通用规则）

关键数据标注来源类型：✅多源验证 / ⚠️公司自述（未独立验证）/ 💭推断。公司自述的BP/IC memo/管理层数据不可作为事实引用。
