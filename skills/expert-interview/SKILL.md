# 专家访谈 Skill

## 角色

设计专家访谈方案，利用专家视角交叉验证投资假设。不是「找专家聊天」，是「拿待验证假设去对质」。

## 前置依赖
- 无硬依赖（可独立触发）
- 被 ind-res/comp-res 调用时：接收上游的待验证假设

## R+1 机制
检测到新疑点/上游更新/用户要补验证时，**先提问确认**再决定是否开新一轮，不自动触发。

## 工作流程


**项目上下文重置（防串项目）**：开始撰写前，确认当前项目名称。报告中所有案例/竞品/数据/人名必须来自当前项目。不可复用上一项目的分析框架作为模板代入。

### 材料检查（强制）
研究前扫描项目下所有已有访谈（见闻录 + 本地访谈文件）。访谈是最高质量的一手信息——必须逐份检查是否有可用素材，不可仅依赖 BP/Datapack。

### Step 1：假设收集
- 从上游研究提取待验证假设
- 分类：技术假设 / 市场假设 / 竞争假设 / 人才假设
- **强制**：每条假设标注来源（哪个报告的哪个章节）和优先级（P0/P1/P2）

### Step 2：专家画像
- 确定需要的专长领域（行业/技术/客户/竞对）
- 按专业度排序：从业者 > 学者 > 观察者
- **强制**：每个专长领域列出推荐的专家来源渠道（具体到机构类型/职位类型，如「前高通CIM芯片设计工程师」「OPPO硬件采购决策者」）

### Step 3：访谈设计
- 每个假设 → 对质问法（不要引导性问题）
- 每个问题附判断标准（✅ 验证通过的回答特征 / ❌ 证伪的回答特征）
- 交叉验证设计：同一假设从不同专家角度提问，标注「交叉验证对」（假设X ← 专家A问法 / 专家B问法）
- **量化追问**：每个关键假设至少1个量化追问（「当前数字是多少？目标数字是多少？什么时间？」）

### Step 4：访谈后沉淀
- 访谈纪要走见闻录入库流程（详见 CLAUDE.md「访谈纪要处理规则」——先调 meeting-minutes-skill 做第一道结构化，再做第二道 AI 精炼）
- 假设验证结论写回上游报告
- 跨项目通用 insight → `知识库/2_wiki/concepts/观点库.md`

## 输出结构

```markdown
# [主题] 专家访谈方案 v[N]

> 基于：[上游报告列表] | 待验证假设 N 条

## 1. 待验证假设清单
（强制表格——假设/分类/来源（报告+章节）/优先级/当前置信度：

| # | 假设 | 分类 | 来源 | 优先级 | 当前置信度 |
|---|------|:---:|------|:---:|:---:|
| H1 | [一句话] | 技术/市场/竞争/人才 | [报告名 §章节] | P0/P1/P2 | 高/中/低 |

至少 5 条假设。标注哪些假设是「已有单方说法、需独立验证」vs「完全未验证的推断」。

## 2. 专家画像
（强制表格——专长领域/为什么需要/推荐来源（机构类型+职位类型）/优先级/替代来源：

| 专长领域 | 为什么需要 | 推荐来源 | 优先级 | 替代来源 |
|------|------|------|:---:|------|
）

至少 3 类专家。）

## 3. 访谈提纲
（按专家类型分节。每类专家包含：
- 背景问题（2-3个，确认专家资质）
- 核心问题（按假设对应，每个问题标注：问题文本 / 对应的假设编号 / 问法类型（开放式/对质式/量化追问）/ 判断标准（✅满意回答特征 / ❌红旗信号）
- 结束问题（1-2个，「还有谁我们应该聊」）

**强制**：每个假设至少1个量化追问。）

## 4. 交叉验证矩阵
（强制表格——关键假设×推荐专家类型：

| 假设 | 专家A | 专家B | 专家C |
|------|:---:|:---:|:---:|
| H1 | 问法摘要 | 不同角度的问法 | — |
| … | | | |

标注哪些假设有 ≥2 个独立验证角度，哪些只有单角度（需标注「[待补充第二验证角度]」）。）

## 5. 访谈后追踪
（模板——访谈日期/专家/关键发现/假设验证结果/新疑点/下次访谈方向。空模板待填充。）
```

## 自检清单

- [ ] 假设清单 ≥5 条？每条有来源+优先级+分类？
- [ ] 每条假设有 ≥1 个量化追问（数字+目标+时间）？
- [ ] 专家画像 ≥3 类？每类有推荐来源+替代来源？
- [ ] 交叉验证矩阵中关键假设有 ≥2 个独立验证角度？
- [ ] 每个问题有判断标准（✅满意 / ❌红旗）？
- [ ] CLAUDE.md「访谈纪要处理规则」：是否记得先调 meeting-minutes-skill 做第一道结构化？
- [ ] **P0 知识库沉积**：exp-intv 完成后，必须将跨项目通用的 investment insight 写入 `concepts/观点库.md`（CLAUDE.md §知识库规则-自动沉淀）。不可跳过。
